## О проекте

В малом и среднем бизнесе (а также в тендерных отделах) до **40% рабочего времени** специалистов, работающих с контрактами, уходит на первичную вычитку договоров контрагентов, а подготовка документов путём копирования старых шаблонов Word приводит к рассинхрону разделов и прямым рискам административных штрафов по ст. 13.11 КоАП РФ (от 300–700 тыс. руб. до 1–6 млн руб. за нарушения ФЗ-152) и финансовых потерь по ГК РФ.

**Модульный конструктор договоров** — это ML/LLM-система поддержки принятия решений (Human-in-the-Loop), которая автоматизирует подготовку и проверку договоров за счёт:
1. **Модульной декомпозиции и построения графа связей:** автоматическое разбиение текста договора на типизированные смысловые блоки (`blocks[]`), выявление пропущенных обязательных разделов (`missing_blocks[]`) и построение графа логических зависимостей между пунктами (`edges[]`) с валидацией через `Pydantic JSON Schema`.
2. **Блочного редактирования с опорой на RAG (Pinecone):** постатейный поиск актуальных норм права РФ (ФЗ-152, ГК РФ, ст. 13.11 КоАП РФ) и эталонных формулировок для исключения галлюцинаций в ссылках и суммах штрафов.
3. **Стресс-тестирования конфликтных сценариев:** моделирование споров сторон («Заказчик задержал оплату», «Отзыв согласия на обработку ПДн», «Проверка локализации БД») с ранжированием рисков по критичности (`critical`, `high`, `medium`) и генерацией безопасных редакций (`safe_alternative`).

### Целевые метрики системы (MVP)
- **Точность декомпозиции договора на блоки (Macro-F1):** $\ge 0{,}85$
- **Полнота выявления заложенных рисков (Risk Recall):** $\ge 0{,}80$ на стресс-корпусе
- **Доля формулировок, принятых юристом без правок (Acceptance Rate):** $\ge 0{,}70$
- **Сокращение полного цикла сборки и вычитки договора (включая HITL):** в 3–4 раза (с 30–40 мин до $\le 5\text{–}8$ мин)

## Установка и контроль качества кода (Ruff и pre-commit)

В репозитории настроены линтер и форматер **Ruff** ([`pyproject.toml`](pyproject.toml)) и хуки **pre-commit** ([`.pre-commit-config.yaml`](.pre-commit-config.yaml)). Подробная инструкция приведена в [`CONTRIBUTING.md`](CONTRIBUTING.md).

```bash
# 1. Установка dev-зависимостей (Ruff, pre-commit) через uv
uv sync --dev

# 2. Установка git-хуков pre-commit
uv run pre-commit install

# 3. Запуск всех проверок по всему репозиторию
uv run pre-commit run --all-files

# 4. Отдельный запуск линтера и форматера Ruff
uv run ruff check .
uv run ruff format --check .
```

## Методология ведения репозитория

- Каждая домашняя работа выполняется в отдельной ветке `hw_n` (например, `hw_1`).
- Слияние в `main` выполняется через **Pull Request (PR)** после прохождения проверок `pre-commit` и кросс-ревью ментором и двумя студентами курса.
