# Руководство по контрибьюции (Contributing Guide)

В этом документе описаны правила работы с репозиторием проекта **«Модульный конструктор договоров»** по курсу **«Проектирование систем машинного обучения»**, настройка окружения разработки, использование линтеров/форматеров и процесс создания Pull Request.

---

## 1. Методология работы с ветками (Git Flow для курса)

- Основная стабильная ветка репозитория — `main`.
- Каждая домашняя работа выполняется в отдельной ветке вида `hw_n`, где `n` — номер домашнего задания (например, `hw_1`, `hw_2`).
- Слияние в `main` происходит только через **Pull Request (PR)** после прохождения автоматических проверок `pre-commit` / `ruff` и получения ревью от ментора и двух студентов курса (кросс-ревью).

---

## 2. Установка зависимостей для разработки

Для контроля качества кода и конфигурационных файлов применяются инструменты **Ruff** (линтер + форматер) и **pre-commit**, зафиксированные в [`pyproject.toml`](pyproject.toml) (группа `[dependency-groups] dev`).

### Вариант А: через пакетный менеджер `uv` (рекомендуется)

```bash
uv sync --dev
```

### Вариант Б: через стандартное виртуальное окружение `venv`

```bash
python3 -m venv .venv
.venv/bin/pip install ruff pre-commit
```

## 3. Линтеры и форматеры (Ruff)

Все настройки **Ruff** находятся в файле [`pyproject.toml`](pyproject.toml):
- Целевая версия: `py310`
- Максимальная длина строки: `120` символов
- Включенные группы правил:
  - `E`, `W` — ошибки и предупреждения `pycodestyle`
  - `F` — `pyflakes` (неиспользуемые импорты и переменные)
  - `I` — `isort` (автоматическая сортировка импортов)
  - `B` — `flake8-bugbear` (поиск потенциальных багов и антипаттернов)
  - `UP` — `pyupgrade` (современный синтаксис Python 3.10+)

### Основные команды Ruff

Проверить код линтером:
```bash
uv run ruff check .
```

Автоматически исправить ошибки линтера (включая сортировку импортов):
```bash
uv run ruff check --fix .
```

Отформатировать код согласно стилю проекта:
```bash
uv run ruff format .
```

Проверить форматирование без изменения файлов (режим CI):
```bash
uv run ruff format --check .
```

## 4. Настройка и использование `pre-commit`

Конфигурация хуков описана в файле [`.pre-commit-config.yaml`](.pre-commit-config.yaml) и включает:
1. Стандартные проверки `pre-commit-hooks`:
   - `trailing-whitespace` — удаление лишних пробелов в конце строк;
   - `end-of-file-fixer` — гарантия пустой строки в конце файла;
   - `check-yaml`, `check-toml`, `check-json` — валидация синтаксиса конфигурационных файлов;
   - `check-added-large-files` — запрет на коммит файлов крупнее 500 КБ;
   - `check-merge-conflict` — проверка отсутствия маркеров конфликта слияния;
   - `detect-private-key` — защита от случайной утечки приватных ключей.
2. Хуки `ruff-pre-commit`:
   - `ruff --fix` — линтинг Python-кода с автоисправлением;
   - `ruff-format` — автоформатирование Python-кода.

### Активация git-хуков локально

После клонирования репозитория и установки dev-зависимостей выполните один раз:

```bash
uv run pre-commit install
```

Теперь при каждом вызове `git commit` все проверки будут запускаться автоматически.

### Ручной запуск на всех файлах репозитория

```bash
uv run pre-commit run --all-files
```

## 5. Порядок выполнения и сдачи домашнего задания

1. Создайте ветку для текущей домашней работы от `main`:
   ```bash
   git checkout -b hw_1
   ```
2. Внесите изменения в дизайн-документ (`docs/ml_system_design_doc.md`) или исходный код (`src/`).
3. Прогоните проверки качества:
   ```bash
   uv run pre-commit run --all-files
   ```
4. Зафиксируйте изменения, отправьте ветку в GitHub и откройте Pull Request в ветку `main`, добавив ментора и кросс-ревьюверов в `Reviewers`.
